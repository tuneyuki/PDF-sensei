# 08. MVP1 の題材と入稿コストの試算

MVP1 で扱う題材を集め、入稿パイプライン（[03](03-knowledge-units-and-teacher.md) §5）の各段で何にお金がかかるかを試算した。

> 金額はいずれも 2026-10 時点の概算。Claude の単価は Anthropic 直販の価格で、Vertex AI 上の Claude は別料金体系のため着手前に [Vertex AI の料金表](https://cloud.google.com/vertex-ai/generative-ai/pricing#claude-models)で確認する。円換算は $1 = 150 円。

## 1. 題材

`scripts/fetch-corpus.sh` で `data/corpus/` に取得する（書籍ファイルはリポジトリに入れない）。層を引数で選ぶ（`core` / `ja` / `en` / `epub` / `all`）。

| 層 | ファイル | 規模 | 性格 |
|---|---|---:|---|
| core | `ja-progit.epub` / `.pdf` | 528p | 日本語・EPUB と PDF がそろう。`compare` の基準。[02](02-ingestion-mvp-validation.md) と同じ版で、`eval/progit-ja.yaml` がそのまま使える |
| core | `en-progit.epub` / `.pdf` | 501p | 英語・二形式そろい |
| core | `en-eloquentjs.epub` / `.pdf` | 463p | 二形式そろい。コード多め |
| ja | `ja-johotsushin-r07.pdf` | 256p | 総務省 情報通信白書 令和7年版。2 段組・図表が極端に多い |
| ja | `ja-ipa-websecurity.pdf` | 115p | IPA 安全なウェブサイトの作り方。日本語の技術文書 |
| ja | `ja-ipa-sql.pdf` | 47p | IPA 安全な SQL の呼び出し方。小規模で反復向き |
| en | `en-d2l.pdf` | 1151p | Dive into Deep Learning。最大規模。数式とコード |
| en | `en-tlcl.pdf` | 555p | The Linux Command Line。端末出力の等幅ブロック |
| en | `en-mml-book.pdf` | 417p | Mathematics for Machine Learning。数式中心 |
| en | `en-think-python.pdf` | 244p | Think Python。素直な技術書 |
| epub | `en-alice.epub` / `en-frankenstein.epub` | — | Project Gutenberg。散文・浅い階層 |

不足していること:

- **日本語 EPUB が Pro Git 1 冊だけ。** 無料で入手できる日本語 EPUB の技術書はほぼない。縦書き・ルビの題材は別途調達が必要。
- **ライセンスが混在している。** `en-mml-book.pdf` は著者配布（再配布不可）、`en-tlcl.pdf` は CC BY-NC-ND。手元の開発・評価には問題ないが、本文を返すサービスとして公開する段階では対象を絞るか、認証付きにする。

## 2. 試算の前提: 題材の量（実測）

| | 文字数 | 推定トークン |
|---|---:|---:|
| 15 ファイルすべて | 約 1,000 万字 | 約 320 万 |
| **サービスに載せる 12 冊**（Pro Git 日英・Eloquent JS は片方の形式だけ） | 約 780 万字 | **約 240 万** |

- EPUB と PDF の両方が要るのは抽出の比較（`compare`）だけで、LLM は使わない。LLM の前処理は 12 冊ぶんで足りる。
- トークンは英語 4 字/トークン、日本語 1.5 字/トークンで換算した概算（±30% 程度）。
- PDF は 12 冊で計約 4,300 ページ。

## 4. お金がかかるのは実質 4 か所

### 4.1 ページ画像を読ませる抽出（最大の変動要因）

1 ページあたり入力約 1,600 トークン（画像）、出力約 1,000 トークン（書き起こし）。**出力の料金が支配的** で、Opus 5.5 なら 1 ページ約 $0.026。

| 適用範囲 | Opus 5.5 | Sonnet 5.5 | Haiku 5.5 |
|---|---:|---:|---:|
| 12 冊の全ページ（約 4,300p） | 約 $110 | 約 $56 | 約 $3 |
| まとまりの判定だけ画像で行う併用（出力約 200 トークン） | 約 $45 | 約 $23 | 約 $1.5 |
| **情報通信白書だけ（256p）** | **約 $7** | 約 $3.5 | 約 $0.2 |

Pro Git などの技術書は文字データからの抽出で足りることを [02](02-ingestion-mvp-validation.md) で確認済み。MVP1 で画像抽出が要るのは情報通信白書ぐらいで、[0.5] Profile で「画像で読むべき本・ページ」を絞れるかがこのコストを決める。

### 4.2 文脈ヘッダ付与

チャンク 1 件ごとに「章の全文 + チャンク」を渡して 1〜2 文を生成する（[01](01-data-model-and-ingestion.md) [5] Enrich）。章が平均 3 万トークンなら 1 章に約 50 チャンクあり、章を 50 回読む。プロンプトキャッシュで単価は下がるが、読む量は減らない（12 冊でキャッシュ読み出し約 1.2 億トークン）。

- コストは本の大きさではなく **章の大きさの 2 乗** に比例する。章が大きい `en-d2l.pdf` が突出する。
- 文脈として渡す範囲を「章」から「節」にすると、節が章の 1/6〜1/10 ならコストもほぼ同じ比率で下がる。
- 「このチャンクは何の話の一部か」を 1 文で書くだけの作業なので、Haiku 5.5 で足りる見込み（約 $2）。

### 4.3 知識カード抽出

出力（JSON のカード）が多く、Opus 5.5 は thinking を切れない（effort で量を調整するだけ）ため、出力の 1〜2 倍程度の thinking トークンが上乗せされる。回答の質に直結するので、上位モデルを使う価値がある。

### 4.4 人のレビュー

金額には出ないが、12 時間は MVP1 で一番重いコストになりうる。入れない場合は評価セットで品質を見張る（[03](03-knowledge-units-and-teacher.md) §8 の未決事項 4）。

## 5. 合計

| 構成 | 入稿 1 回通し（12 冊） |
|---|---:|
| **推奨**: 画像抽出は白書だけ、文脈ヘッダは Haiku、要約は Sonnet、カードは Opus、図の説明文なし | **約 $45〜60（7,000〜9,000 円）** |
| 全部 Opus、画像抽出も全ページ | 約 $250（約 3.7 万円） |
| 全部 Haiku | 約 $10（約 1,500 円） |

- 上の額は 1 回通しの額。プロンプトを調整しながら何度も流すと回数ぶんかかるため、**予算は 1 回通しの 2〜3 倍** を見ておく。
- プロンプトの調整は `ja-ipa-sql.pdf`（47p、全体の約 1%）と Pro Git の 1 章で行い、固まってから全体を 1 回流す。
- 前処理はリアルタイム性が不要なので、バッチ API（Vertex AI ではバッチ予測）で約半額になる。ただしバッチではプロンプトキャッシュの当たり方が不安定になるため、文脈ヘッダ付与は通常 API + キャッシュのほうが安い場合がある。少量で両方試して比べる。

## 6. 入稿以外で継続的にかかるもの

| 項目 | 目安 |
|---|---|
| 回答 1 件あたりの LLM 代（[07](07-answer-latency.md) の案 A: 分解・選定・回答で LLM 3 回） | Opus 5.5 で約 $0.15（約 20 円）、Sonnet 5.5 で約 $0.08 |
| 評価の実行（回答の質を LLM で採点する場合） | Pro Git の 40 問で 1 回約 $4（Opus 5.5）。プロンプトを直すたびに回す |
| 検索だけの評価（hit@k） | 埋め込みのみ。ほぼ無料 |

## 7. 決めること

1. **画像抽出をどの本・ページに使うか。** Profile 段で絞る。MVP1 は情報通信白書だけで足りる見込み。
2. **段ごとのモデルの割り当て。** 文脈ヘッダは Haiku、知識カードは上位モデル、を基本線とする。
3. **人のレビューを入れるか。** 入れないなら評価セットを先に整備する。
4. **`en-d2l.pdf` を MVP1 に含めるか。** 文脈ヘッダ付与のコストが突出するため、外すか、文脈の範囲を節にする。

## 8. 次のステップ

1. `ja-ipa-sql.pdf` 1 冊で入稿を通し、`usage` の実トークン数を測る。実測から 12 冊ぶんに引き伸ばして本書の試算を更新する（誤差 ±30% → 数 %）。
2. Vertex AI 上の Claude と `gemini-embedding-001` の単価・リージョンを確認する。
