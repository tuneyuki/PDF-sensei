# 11. 書籍カタログの管理

書籍ごとに、作品タイトル・著者・出版社などの書誌情報、公開期間、おすすめなどのキャンペーン、利用者向けのサンプルプロンプト（「夏バテに効くメニューを提案して」など）を共通のレコードとして持ち、一覧で管理できるようにする。

## 1. 基本方針

### 1.1 「中身」と「カタログ」を分ける

| | 中身（コンテンツ） | カタログ |
|---|---|---|
| 何か | 入稿の成果物（Canonical・チャンク・知識カード）と、その版 | 書誌情報・公開期間・キャンペーン・サンプルプロンプトなど、本の「見せ方・売り方」 |
| 単位 | 版（`book_id` + `version`） | 本（`book_id`）。版をまたいで 1 つ |
| 作り方 | 入稿パイプラインが生成し、人は仕組みを直す（[09](09-review-strategy.md)） | 人が編集する。入稿は初期値を提案するだけ |
| 変わる頻度 | 入稿・改訂のとき | 随時（キャンペーンは週・月単位） |

カタログは版に属さないので、改訂版を公開してもカタログの設定（公開期間・キャンペーン・プロンプト）はそのまま引き継がれる。

### 1.2 入稿は提案、人の編集が勝つ

書誌情報の多くは入稿時に取れる（EPUB の OPF、PDF のメタデータ）。ISBN からの外部の書誌検索は使わない（§7 の決定）。これを **初期値として提案** し、人が編集した項目は以後の入稿で上書きしない（後勝ち。人の編集が後）。

- 項目ごとに出所（`ingest` / `manual`）を記録する。
- 入稿で取れた値が、人が編集した値と違う場合は上書きせず、例外キュー（[09](09-review-strategy.md) §3.1）に「書誌の差分」として出す。

### 1.3 公開できるかは 1 か所で判定する

ある本を利用者に見せてよいかは、複数の条件の組み合わせで決まる。判定を 1 つの関数（DB のビュー）にまとめ、チャット API・一覧・検索のすべてがそれを使う。

```
公開中（利用者の区分ごと） = その区分（無料 / 有料）の公開期間の中にある
       ∧ 権利の期間の中にある
       ∧ 公開中の版がある（books.active_version）かつ受け入れ判定に合格している
       ∧ 止められていない（[10](10-post-release-fixes.md) ①）
       ∧ カタログの状態が published
```

判定は利用者の区分（§2.2.1）を引数に取る: `visible_books(区分, 時刻)`。

### 2.2 権利と公開期間

公開期間は、出版社との契約（権利の期間）と、運用上の公開期間の 2 段で持つ。

| 項目 | 内容 |
|---|---|
| 権利の期間 | 契約で使ってよい期間。権利者、許諾の範囲（本文の引用の可否・量など）も記録する |
| 公開期間 | 実際に利用者に見せる期間。**権利の期間の内側でなければ保存できない** ようにする |
| 公開期間は複数持てる | 期間限定の公開、一時的な取り下げと再公開などのため |

権利の期間が近く切れる本（例: 30 日以内）は一覧で警告する。

#### 2.2.1 無料ユーザー用・有料ユーザー用の出し分け（決定）

**書籍ごとに、無料ユーザー向けと有料ユーザー向けの公開期間をそれぞれ持つ。**

| 例 | 無料ユーザー | 有料ユーザー |
|---|---|---|
| 誰でも読める本 | 公開 | 公開 |
| 有料会員限定の本 | 非公開 | 公開 |
| 期間限定で無料開放する本 | 4/1〜4/30 だけ公開 | 常時公開 |

- 公開期間のレコードに区分（`free` / `paid`）を持たせる。区分ごとに複数の期間を持てる。
- 前提: **有料ユーザーは、無料ユーザーに公開中の本も読める**（有料は無料を含む）。判定は「有料ユーザー = 無料の公開期間 ∪ 有料の公開期間」とする。
- どちらの期間も権利の期間の内側に限る。
- サンプルプロンプトの表示は、見る人の区分で `visible_books` を通して絞る。キャンペーンの表示はフロントエンドが制御する（§2.3）が、そのために本ごとの公開状態（区分別）を返す。

### 2.3 キャンペーン（フラグ）

> **後の決定（後勝ち）**: キャンペーンの表示（どこに・どの順で・どう見せるか）は **フロントエンドがフラグを見て制御する**。こちらが持つのはスキーマ（データ）だけで、表示場所・並べ方の設計はこちらの範囲外。当初の「キャンペーンを独立したレコードにし、表示場所も持つ」案はこれで置き換える。

書籍ごとに **キャンペーン用のフラグ** を持つ。種類が増えるたびに列を足さなくて済むよう、フラグは「キー + 値 + 期間」の行で持つ。

| 項目 | 内容 |
|---|---|
| キー | `recommended`（おすすめ）、`new`（新着）、`summer2027`（特集）など。使えるキーは定義表に登録したものだけ（打ち間違い防止） |
| 値 | 既定は真偽値。並び順や見出しなど、フロントエンドが必要とする付随情報は任意の JSON で持てる |
| 期間（任意） | 開始・終了。期間外のフラグは無効として返す |
| 区分（任意） | 無料 / 有料のどちら向けか（§2.2.1）。省略時は両方 |

- フラグの意味と見せ方はフロントエンドが決める。こちらはキーの定義表（キー・説明・値の形）を共有し、値の形を検証して保存する。
- **アクセスの制御はこちらで行う。** フロントエンドの表示とは別に、チャット API は利用者の区分で公開中の本（§1.3）にしか質問を受け付けない。フロントエンドには、本ごとの公開状態（区分別）もフラグと一緒に返す。

#### 2.3.1 終わりのないキャンペーン（後の決定）

「定番のおすすめ」のように **未来永劫続くキャンペーン** も想定する。期限付きのもの（夏の特集など）と同じ仕組みで扱い、次のように決める。

| 論点 | 決定 |
|---|---|
| 無期限の表し方 | 終了日時を **空（NULL）= 無期限** とする。開始日時が空なら即時に有効。`9999-12-31` のような仮の日付は使わない（集計や表示で誤解を生むため） |
| キーの種類 | 定義表でキーごとに「常設（終了日時なしを許す）」か「期間限定（終了日時が必須）」かを決める。期間限定のキーに終了日時なしで登録しようとしたら保存しない（付け忘れで特集が永久に残る事故を防ぐ） |
| 同じキーを繰り返し使う | 1 冊に同じキーの期間を複数持てる（例: 去年の夏と今年の夏）。ただし同じ本・同じキー・同じ区分で期間が重なる行は保存しない |
| 毎年の繰り返し | 「毎年 7/1〜8/31」のような繰り返しを 1 行で持てる（`recurrence = yearly` と月日の範囲、日本時間）。終了日時を空にすれば、毎年の特集をずっと続けられる |
| キーの寿命 | キーは名前を変えず、再利用もしない（意味が変わると過去の記録と混ざる）。使わなくなったキーは削除せず「廃止」にする。廃止したキーは新しく付けられないが、過去の行と変更記録は残る |
| 値の形の変化 | 長く使ううちに値の形（JSON）が変わりうるため、定義表で値の形に版を持たせ、各行に保存時の版を記録する。形を変えるときは古い形の行を読めるようにするか、移行する |
| 本の公開との関係 | フラグは公開期間を延ばさない。無期限のフラグが付いていても、本の公開期間・権利の期間が終われば見えなくなる（§1.3 の判定はフラグと独立）。権利が近く切れる本に無期限のフラグが付いていれば一覧で警告する |
| 記録 | 終わったフラグの行は消さずに残す（いつからいつまで何が付いていたかを説明できるように）。変更は `catalog_changes` に記録する |

### 2.4 サンプルプロンプト

本の画面に、利用者が押すだけで質問できる例文を出す。

| 項目 | 内容 |
|---|---|
| 本文 | 「夏バテに効くメニューを提案して」「ピエールってどういう人物？」 |
| 種類 | 要約 / 解説 / 推薦 / 当てはめ など（[03](03-knowledge-units-and-teacher.md) のユースケース） |
| 表示期間 | 季節もの（夏バテ、紅葉）は期間を付ける。期間外は出さない |
| 並び順・状態 | 下書き / 承認済み。承認済みだけを出す |
| 出所 | 自動生成 / 人が作成 |

作り方:

1. **入稿時に自動で候補を作る。** 特徴パッケージの定番の使い方と、LLM による使い方の提案（[04](04-architecture-traits.md) §5、パイプラインの [5.95]）から候補を出す。
2. **人が選んで承認する。** 季節もの・キャンペーンに合わせたものは人が足す。
3. **サンプルプロンプトは必ず答えられるものにする。** 承認済みのプロンプトを、その本の質問テスト（[09](09-review-strategy.md) §3.3）に自動で加える。新しい版で答えられなくなったら、受け入れ判定の段階で検出する。

### 2.5 状態

| 状態 | 意味 |
|---|---|
| `draft` | 登録したが、まだ公開の準備中（中身がない段階でも作れる。発売前の予約登録など） |
| `ready` | 公開できる状態（受け入れ判定に合格した版がある） |
| `published` | 公開する（実際に見えるかは §1.3 の判定） |
| `suspended` | 一時停止（権利の申し立てなど。[10](10-post-release-fixes.md) ① の本単位の停止と連動） |
| `retired` | 提供終了。会話履歴の表示のために記録は残す |

## 3. データ構造（案）

既存の `books` テーブル（[05](05-index-and-search.md)）をカタログの中心に広げる。

```sql
-- 本（カタログの中心）。book_id は ULID（[10] §8）
ALTER TABLE books ADD COLUMN ... ;   -- 下記の項目を追加
--   subtitle, title_kana, original_title, publisher, imprint, series_id, series_no,
--   isbn_print, isbn_ebook, published_on, genre, traits text[], description,
--   cover_asset, age_rating, notes, catalog_status, field_sources jsonb,
--   updated_at, updated_by

CREATE TABLE book_contributors (      -- 著者・訳者・監修など
  book_id text REFERENCES books, ord int, name text, name_kana text,
  role text,                          -- author | translator | editor | supervisor | illustrator
  PRIMARY KEY (book_id, ord)
);

CREATE TABLE book_rights (            -- 契約上の権利
  rights_id text PRIMARY KEY, book_id text REFERENCES books,
  holder text, starts_at timestamptz, ends_at timestamptz,
  quote_policy text,                  -- 本文の引用の可否・量（[03] §8 の未決事項 3 と連動）
  contract_ref text, notes text
);

CREATE TABLE book_publications (      -- 公開期間（区分ごとに複数可。権利の期間の内側に限る）
  publication_id text PRIMARY KEY, book_id text REFERENCES books,
  audience text NOT NULL,             -- free | paid（§2.2.1）
  starts_at timestamptz, ends_at timestamptz, reason text
);

CREATE TABLE flag_definitions (       -- 使えるフラグのキー（フロントエンドと共有）
  flag_key text PRIMARY KEY, description text,
  kind text NOT NULL,                 -- perpetual（終了日時なしを許す）| limited（終了日時が必須）（§2.3.1）
  status text NOT NULL DEFAULT 'active', -- active | deprecated（削除・再利用はしない）
  value_schema jsonb,                 -- 値の形（JSON Schema）の現在の版。保存時に検証する
  value_schema_version int NOT NULL DEFAULT 1,
  created_at timestamptz DEFAULT now()
);
CREATE TABLE book_flags (             -- 本ごとのキャンペーン用フラグ（§2.3）。同じキーの期間を複数持てる
  flag_id text PRIMARY KEY,
  book_id text REFERENCES books, flag_key text REFERENCES flag_definitions,
  value jsonb NOT NULL DEFAULT 'true', -- 並び順・見出しなど任意
  value_schema_version int NOT NULL,  -- 保存時の値の形の版
  audience text,                      -- free | paid | NULL（両方）
  starts_at timestamptz,              -- NULL = 即時
  ends_at timestamptz,                -- NULL = 無期限（limited のキーでは禁止）
  recurrence text,                    -- NULL | yearly（毎年繰り返す）
  recur_from text, recur_to text,     -- yearly のときの月日の範囲（'07-01'〜'08-31'、日本時間）
  CHECK (ends_at IS NULL OR starts_at IS NULL OR starts_at < ends_at)
  -- 同じ本・キー・区分で期間が重なる行は禁止（btree_gist の EXCLUDE 制約、または保存時の検証）
);

CREATE TABLE book_sample_prompts (
  prompt_id text PRIMARY KEY, book_id text REFERENCES books,
  text text, intent text, ord int, locale text,
  starts_at timestamptz, ends_at timestamptz,   -- 季節もの
  status text,                        -- draft | approved | retired
  source text                         -- auto | manual
);

CREATE TABLE catalog_changes (        -- 変更の記録（誰が・いつ・何を・なぜ）
  change_id bigserial PRIMARY KEY, at timestamptz DEFAULT now(), actor text,
  entity text, entity_id text, before jsonb, after jsonb, reason text
);

-- 公開できるかの判定（§1.3）。チャット API・一覧・検索はこのビューだけを見る
CREATE FUNCTION visible_books(audience text, at timestamptz) ... ;  -- 区分と時刻を引数に取る
```

時刻は `timestamptz` で持ち、運用・表示は日本時間で行う。

## 4. 一覧での管理

### 4.1 一覧で見たいもの

| 列・絞り込み | 用途 |
|---|---|
| タイトル・著者・出版社・シリーズ | 探す |
| 状態、公開中かどうか（§1.3 の判定結果と、公開できない理由） | 「なぜ見えないのか」がすぐ分かるようにする（期間外、権利切れ、受け入れ判定待ち、停止中…） |
| 公開中の版、受け入れ判定の結果、QA の状態 | 中身の状態 |
| 公開期間・権利の期間（**期限が近いものを警告**） | 契約の管理 |
| 有効なフラグ | 販促の設定の確認（見せ方はフロントエンド） |
| 承認済みのサンプルプロンプトの数（0 件を警告） | 本の画面の品質 |
| 未処理の例外（書誌の差分など） | 作業の残り |

### 4.2 編集のしかた

- **最初は表計算での一括編集を主にする。** 一覧を CSV / スプレッドシート形式で書き出し、編集して取り込む。取り込みでは検証（公開期間が権利の期間の内側か、必須項目、日付の前後関係など）を行い、変更は `catalog_changes` に記録する。
- 管理画面は、運用の形が固まってから作る（[09](09-review-strategy.md) §8 のレビュー画面と同じ方針）。**当面は作らない（決定）。** CSV での書き出し・取り込みとコマンドで管理する。
- コマンドの例（実装は未着手）: `sensei catalog export` / `sensei catalog import` / `sensei catalog show <book_id>`。

## 5. ステージングと本番での扱い

カタログは、項目によって「どちらの環境で編集するか」が違う（[06](06-deployment-gcp.md) §2.3）。

| 項目 | 編集する環境 | 本番への反映 |
|---|---|---|
| 書誌情報、サンプルプロンプト（自動生成・承認） | ステージング | 版の昇格と一緒に反映する。本番で直した場合はステージングに書き戻す |
| 権利・公開期間・キャンペーン用フラグ・状態 | **本番**（運用の操作） | 本番が正。ステージングへは参考として複製する |

- 公開期間やキャンペーンの切り替えは、中身の昇格を待たずに本番で即時に行えるようにする。
- 本で 1 つの `book_id`（ULID）で両環境をそろえる（[10](10-post-release-fixes.md) §8）。カタログのレコードは、ステージングでの初回入稿時（または発売前の予約登録時）に作る。

## 6. チャットボットとの関係

- **本の選択**: 利用者が選べる本は、その利用者の区分で `visible_books` に入っているものだけ。
- **公開期間が終わった本の会話（決定）**: 新しい質問は受け付けず、**過去の会話も見せない**。利用者の区分が変わって読めなくなった本（有料会員をやめた、など）も同じ扱いにする。会話のデータを削除するか、見えなくするだけかは、会話履歴の保持方針と合わせて決める。
- **再び読めるようになった場合**（再公開・有料会員に戻った）に過去の会話を再び見せるかは未決（§7）。
- **サンプルプロンプト**: 本の画面に、表示期間内・承認済みのものを並び順に出す。押すとそのまま質問として送る。
- **引用の量**: 権利の許諾範囲（`quote_policy`）に応じて、回答に載せる本文の量を変えられるようにする（[03](03-knowledge-units-and-teacher.md) §8 の未決事項 3）。

## 7. 未決事項

決定済み（2026-10-26）:

- 公開期間が終わった本の過去の会話は **見せない**（§6）。
- 利用者の区分による出し分けを **する**。書籍ごとに無料ユーザー用・有料ユーザー用の公開期間を持つ（§2.2.1）。
- ISBN からの書誌情報の外部取得は **しない**。書誌情報は入稿時に原本から取れる値を初期値とし、あとは人が入力する。ISBN は項目として持つ（手入力・原本から取得）。
- 管理画面は **当面作らない**。CSV とコマンドで管理する。
